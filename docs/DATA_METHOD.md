# データと方法

## 使うデータ

| データ | 提供 | 使う内容 |
|---|---|---|
| 500mメッシュ別将来推計人口（令和6年国政局推計） | 国土数値情報（国土交通省） | 令和2年国勢調査が基準。2025〜2070年の5年ごと、男女計の5歳階級別人口。都道府県単位で配布 |
| 小学校区データ | 国土数値情報（国土交通省） | 公立小学校の通学区域のポリゴン、学校名、所在地など |
| 廃校施設等活用状況実態調査（令和6年度） | 文部科学省 | ステップ5のヒント（活用用途の割合） |

## 計算

1. **メッシュの位置**：メッシュコードから緯度経度を計算する（図形ファイルは使わない）。
2. **学区への配分**：各メッシュに 4×4 の点を等間隔に置き、点が入る学区に人口を等分して足す。メッシュ内で人口が一様という面積按分と同じ仮定。
   - 学区が重なる場所の点は、重なった学区の数で等分する。
   - どの学区にも入らない点は「未配分」として集計し、検査レポートに出す。
3. **小学生の年齢**：6〜11歳 ＝（5〜9歳）× 4/5 ＋（10〜14歳）× 2/5。5歳階級の中は各歳に等しく分かれていると仮定。
4. **年齢の階段用**：2025年の0〜11歳を各歳に等分したもの。
5. **学級数**：全校の人数を6学年に等分し、国の標準で計算する。同学年35人まで。2つの学年で16人以下（1年生を含むときは8人以下）なら複式学級。

アプリ側の補正：子どもが実際の全校児童数を入れたら、「実際の人数 ÷ 2025年の推計」を全部の年に掛ける。

## 学区データの無い市区町村（おおよその区域）

国土数値情報の小学校区データは、自治体によって提供されていない。福岡県では52市区町村分が収録され、福岡市・北九州市（政令指定都市の全区）などが含まれていなかった（2026-11-14、inspect で確認）。

これらの市区町村では、国土数値情報「学校」の位置を使う。

1. 学区データで配分できた子どもが5%未満の市区町村を「学区データなし」とみなす。
2. その市区町村の公立小学校を選ぶ。学校コードがあれば、先頭2文字が `B1`（小学校）かつ5文字目が `2`（公立）のもの。無ければ名前が「小学校」で終わり、附属・私立を含まないもの。
3. メッシュに置いた各点のうち、学区に入らなかった点を、そのメッシュの市区町村の中でいちばん近い学校に割り当てる（ボロノイ分割と同じ考え方）。境界をまたぐメッシュ（`SHICODE` が `40133_40134` のもの）は、並んだ市区町村のうち学区データの無いものすべての学校を候補にする。学区に配分済みの点は使わないので、二重には数えない。
4. 地図には、割り当てた点の凸包を点線で描き、画面に「おおよその区域」であることを表示する。

本当の学区は道路や町丁目で区切られ、学校から最も近い場所とは限らない。したがって学校ごとの人数のずれは、学区データのある市区町村より大きい。市区町村全体の合計は変わらない。学校の位置データも無い市区町村は「学区データなし」として選択肢に出し、計算しない。

## 検査

`build` は毎回、次を出します（`--opendata` を付けると `report_XX.json` に保存）。

- 保存則：配分した合計 ＋ 未配分 ＝ メッシュの合計（誤差は 0 になるはず）
- 未配分の割合：学区データが無い区域の大きさの目安
- 市区町村ごとの配分率：0.9 未満の市区町村は警告。学区データが未整備の可能性が高い
- 重なりの割合：学区ポリゴン同士の重複の目安
- 2025年の推計が1人未満で出力しなかった学区の一覧

## 公式のコード表で確かめたこと（2026-11-14）

国土数値情報「メッシュ別将来推計人口（R6国政局推計）」のデータ項目一覧で、次を確認した。

- 列は `MESH_ID`（メッシュコード）、`SHICODE`（市町村コード）、2020年の総数、そのあと年ごとに98項目。
- 年ごとの並びは、秘匿記号 `HITOKU20XX`、合算先 `GASSAN20XX`、男女計の秘匿無し総数 `PTN_20XX`、総数 `PT00_20XX`、5歳階級 `PT01`〜`PT20`（01＝0〜4歳）、合計 `PTA`（0〜14歳）〜`PTE`、比率 `RTA`〜`RTE`。続いて男（PM）、女（PF）が同じ並び。
- 秘匿されたメッシュは記号 `*` で値は0。その人口は記号 `@` の合算先メッシュに足されている。したがって、値をそのまま使えば合計は保たれる。

テスト用の合成データ（`pipeline/tests/test_pipeline.py`）は、この並びと秘匿・合算をそのまま再現している。これにより判定の不具合を1つ見つけて直した。秘匿記号の列（空欄は0と読まれる）と総数の列が並ぶため、「0＋0＋総数＝総数」を年齢の内訳と取り違えていた。いまは、3列とも中身のある数字であることを条件にしている。

## 確認済み（福岡県、2026-11-14）

国土数値情報の実ファイル（`A27-23_40_GML.zip`、`500m_mesh_2024_40_GML.zip`、`P29-23_40_GML.zip`）で確かめた。

1. **小学校区データの属性名と同梱形式**。zip に GeoJSON・シェープファイル・GML（XML）が一緒に入っている。属性は `A27_001`（行政区域コード）、`A27_002`（設置主体）、`A27_003`（学校コード）、`A27_004`（学校名）、`A27_005`（所在地）で、中身からの判定は正しく当たった。学校の位置は小学校区の zip には入っておらず、国土数値情報「学校」（P29）を別にダウンロードする。
2. **市区町村名**。福岡市・北九州市の区も「福岡市早良区」「北九州市八幡西区」のように正しく出た。72市区町村すべてに名前が付いた。福岡県の学区データには一部事務組合立の学校が無かったので、その表示は未確認。
3. **ファイルの大きさ**。学校704校（学区データ360校＋学校の位置からの補い344校。利用条件で朝倉市の学区を除いた後の数）、メッシュ11,336件で、`build-all` は約27秒、`app/data/pref_40.js` は約0.68MB。スマートフォンでの読み込み時間はまだ測っていない。

実ファイルで分かったこと：

- **学校の位置データ（P29）には幼稚園なども入っている**。小学校・中学校・高校・幼稚園・認定こども園などが学校種コード順に並び、先頭の数百件は幼稚園（名前が「〜園」で終わる）。属性の判定が先頭400件だけを見ていたため学校名の列を見つけられず、`build-all` が失敗した。いまはファイル全体から等間隔に400件を取って判定する（テスト `test_detect_fields_when_kindergartens_come_first`）。
- **`SHICODE` に複数の市区町村コードが入るメッシュがある**。市区町村の境界をまたぐメッシュは `40133_40134` のように「_」でつながっている。いまはこれを市区町村のリストとして読み、境界のメッシュを市区町村そのものとは扱わない（「学区データなし」の判定は1つの市区町村だけのメッシュで行う）。これで福岡県の未配分は5.5%から1.1%に下がった（テスト `test_gap_fill_with_straddling_meshes_conserves_total`）。
- **40211 は筑後市**（柳川市は 40207）。

## まだ確かめていないこと（実ファイルで最初に確認する）

1. **CSV の文字コードと数値の書式**。UTF-8 / Shift_JIS のどちらでも読む。桁区切りのカンマも除く。（福岡県のメッシュは GML だけだったので、CSV は未確認）
2. **福島県など、推計の扱いが特殊な区域**。

## 読み取りの限界

- 学区に住む子どもの推計であり、在籍児童数ではない（私立・国立、学校選択制、区域外就学）。
- 推計は市区町村の推計に合うよう調整されているが、小さな区域ほど誤差が大きい。
- 学区は整備年度の区域。以後の統合や区域変更は入っていない。
- 国の学級編制の標準で計算しており、自治体独自の少人数学級は入っていない。
- 福島県の一部など、推計の対象外の区域がある可能性がある（実データで確認する）。

## 利用条件

- 国土数値情報は、データごとに利用条件が定められている。小学校区データは自治体ごとに条件が異なり、商用利用できない自治体がある。
- このアプリは非営利の教育目的だが、公開前にダウンロードページの利用条件一覧で、対象の自治体を確認する。条件に合わない自治体は生成対象から外す。
- 出典の表示：「国土数値情報（国土交通省）を加工して作成」。アプリの先生向けページと提案カードに入れてある。
- 副産物の学区別将来児童数 CSV を公開するときは、加工データであること、推計であること、学区データの整備年度を明記する。
