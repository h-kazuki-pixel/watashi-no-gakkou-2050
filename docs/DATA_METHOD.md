# データと方法

## 使うデータ

| データ | 提供 | 使う内容 |
|---|---|---|
| 500mメッシュ別将来推計人口（令和6年国政局推計） | 国土数値情報（国土交通省） | 令和2年国勢調査が基準。2025〜2070年の5年ごと、男女計の5歳階級別人口。都道府県単位で配布 |
| 小学校区データ | 国土数値情報（国土交通省） | 公立小学校の通学区域のポリゴン、学校名、所在地など |
| 学校（令和5年度） | 国土数値情報（国土交通省） | 学校の位置・学校コード・行政区域コード・休校区分。学区データの無い市区町村の「おおよその区域」と、地図のピンに使う |
| 廃校施設等活用状況実態調査（令和6年度） | 文部科学省 | ステップ5のヒント（活用用途の割合） |
| アドレス・ベース・レジストリ 全国 町字マスター | デジタル庁 | 大字・町名と小字の名前と読み（カナ）。学校名の読み（ひらがなで さがす）だけに使う。下の「学校名の読み」 |

## 計算

1. **メッシュの位置**：メッシュコードから緯度経度を計算する（図形ファイルは使わない）。
2. **学区への配分**：各メッシュに 4×4 の点を等間隔に置き、点が入る学区に人口を等分して足す。メッシュ内で人口が一様という面積按分と同じ仮定。
   - 学区が重なる場所の点は、重なった学区の数で等分する。
   - どの学区にも入らない点は「未配分」として集計し、検査レポートに出す。
   - 学区の区域は、**部分（ポリゴン）ごとに「外側の輪 − 穴の輪」を作り、部分を合わせたもの**。同じ学校の部分が重なる所は1回だけ数える。
     同じ学校が複数の地物に分かれているときも、まとめて1つの区域にする。乱れた図形の扱いは下の「学区の図形」。
3. **小学生の年齢**：6〜11歳 ＝（5〜9歳）× 4/5 ＋（10〜14歳）× 2/5。5歳階級の中は各歳に等しく分かれていると仮定。
4. **年齢の階段用**：2025年の0〜11歳を各歳に等分したもの。
   **子どものいないメッシュは使わない。** 6〜11歳（3. の式）が2025〜2070年のすべての年で0で、2025年の0〜11歳（4. の式）も0のメッシュには点を置かない。
   値が0なので合計は変わらないが、おおよその区域の点にもならない（下の「割り当たる点が無い学校」）。
5. **学級数**：全校の人数を6学年に等分し、国の標準で計算する。同学年35人まで。2つの学年で16人以下（1年生を含むときは8人以下）なら複式学級。

アプリ側の補正：子どもが実際の全校児童数を入れたら、「実際の人数 ÷ 2025年の推計」を全部の年に掛ける。

## 画面に出す人数の丸め

推計は小数で持ち、画面には四捨五入した整数を出す。同じ人数が画面によって違って見えないように、次のようにそろえる。

1. **いまの人数・2050年の人数**：`est`（実際の人数で補正したときは補正後）を四捨五入する。
2. **変化率**：1. の丸めた2つの人数から出す。子どもが画面の数で計算した値と同じになる。
3. **年齢の階段（ステップ4）**：0〜11歳の12本に同じ倍率を掛けて、6〜11歳の合計を 1. のいまの人数にそろえる（`est` と `ages` はどちらも小数1けたで保存しているので、そのままだと合計が最大0.3人ほど食い違う）。そのあと11歳から0歳へ累積し、累積を丸めた差を各歳の整数にする。2025年の小学生の合計はいまの人数と一致し、年を進めても各世代の数は変わらない。どの連続した6本の合計も、小数の合計と1人未満しかずれない。

2026-11-17 に直す前は、三阪小（いわき市）がステップ1で13人、ステップ4の文で12人、棒の合計で14人と出ていた。全国では、棒の合計が いまの人数と違う学校が13,993校あった。

## 学区の図形

国土数値情報の小学校区データの図形は GeoJSON を使う（部分ごとに外側の輪と穴の輪が分かれている）。シェープファイルしか無いときは、
輪の向きで部分を組み立てる：いちばん大きい輪と同じ向きの輪を外側の輪、逆向きの輪を穴の輪とし、穴の輪は頂点のいちばん多くが内側にある外側の輪に付ける。

全国の予行（2026-11-16、45都道府県）で、次の乱れた図形が見つかった。どれも `report_XX.json` の `geometry_issues` に一覧で出す。

1. **同じ輪の重複**（`duplicate_rings`）：1つの学校の中で、同じ穴の輪（または同じ外側の輪）が2回以上入っている（千葉県旭市の鶴巻小など）。
   座標の並びが同じ輪（始点と向きは問わない）は、2つ目からを取り除く。以前の偶奇規則では、2つの穴が打ち消し合って穴の中の子どもを数えていた。
2. **外に出た穴**（`hole_outside_outer`）：穴の輪の面積の1%を超える部分が、その部分の外側の輪の外にある。
   面積は、穴の輪を囲む長方形に 200×200 の格子の点を置き、穴の輪の内側の点の数で測る（頂点だけでは、輪が接しているだけの穴まで当たってしまう）。
   - **穴の輪のうち、外側の輪の外にある部分は区域に入れる。外側の輪の内側にある部分は穴として抜く。**
     つまり区域は「外側の輪 − 穴の輪」と「穴の輪 − 外側の輪」を合わせたもの。どの学校にも同じ決まりを使う。
   - ただし、外側の輪の外にある部分（穴の輪の内側で外側の輪の外の点）の半分以上がほかの学校の学区（区域は上と同じ決め方）に入っていれば、
     その部分は入れない（穴の輪はそのまま穴として扱う）。予行ではこの場合に当たる学校は無かった。
   - ほかの学校の学区には、利用条件で除く前の学区データ全部を使う。同じ学校の別の地物は「ほかの学校」に数えない。
   - 予行で当たった6校のうち、本当にはみ出していたのは3校（石川県七尾市の天神山小、長野県上田市の菅平小、三重県御浜町の御浜小）。
     3校とも、はみ出した部分はどの学区にも入っていなかった（となりの飛び地が穴として入っているとみられる）。
     御浜小の穴の輪のうち外側の輪の内側の部分は、神志山小の学区だった。御浜小はシェープファイルではこの輪が外側の輪と同じ向き（別の部分）で、
     GeoJSON と形が違う。ほかの3校（東京都板橋区の新河岸小、京都府井手町の三訪小、長崎県島原市の碩台小）は、穴の輪が外側の輪に接しているだけだった。
3. **部分の重なり**（`overlapping_parts`）：同じ学校の部分どうしが重なっている。重なりは1回だけ数える（上の決め方のとおり）。
   重なりは、2つの部分を囲む長方形の重なりに 200×200 の格子の点を置いて調べ、重なりのおおよその面積（`overlap_km2`）を出す。
   境界を共有しているだけの部分は当たらない（福岡県の樋田小は、予行の頂点による調べ方では当たったが、重なりは約1㎡で、格子の点には当たらない）。

## 学校の位置（地図のピン）

学区データには学校の位置が無い。学区データのある学校の位置も、国土数値情報「学校」（P29）から取る。

1. 学校コードで引く。ただし、P29 でその学校コードの学校がある市区町村が、学区データの市区町村と同じときだけ
   （茨城県古河市の学区データの上大野小・下大野小には、水戸市の上大野小・下大野小の学校コードが入っている）。
2. 学校コードで引けなければ、（市区町村, 設置者を外した学校名）で引く。
3. どちらでも見つからなければ、学区の重心を使い、`report_XX.json` の `location_fallback` に一覧で出す。
4. P29 の位置が、その学校の学区の外にある学校は `location_outside_district` に一覧で出す（位置はそのまま使う）。
5. 政令市の学区データが市のコードで入っているときは、P29 の区のコードを市のコードに読み替えてから引く。

## 元データの行政区域コードや学校コードの誤り

全国の予行（2026-11-16）で、次の誤りが見つかった。

1. **設置者の名前と行政区域コードが合わない学校**（P29）。愛知県の P29 では、稲沢市立下津小学校の行政区域コードが一宮市（23203）だった。
   P29 から学校を選ぶとき（おおよその区域の候補と、学区データに入っていない学校の候補）は、学校名の先頭の設置者
   （「○○市立」「○○町立」「○○村立」「○○区立」。郡名は外す）が、その行政区域コードの公立学校（学校コードの5文字目が 2）の設置者で
   いちばん多いもの（同数で決まらなければ判定しない）と違う学校を使わない。政令市の区は、区の学校の設置者が市なので、市の名前と比べることになる。
   組合立の学校と、設置者が名前に無い学校は外さない。外した学校は `report_XX.json` の `owner_mismatch_excluded` に出す。
2. **学区データ（A27）の学校コードが、P29 では別の市区町村の学校のもの**。茨城県古河市の学区データの上大野小・下大野小には、
   水戸市の上大野小・下大野小の学校コードが入っている。学校は学区データのとおり古河市の学校として出す。
   id には学校コードを使わず「市区町村コード-番号」にする（水戸市の学校と id が重ならないように）。`district_code_other_city` に出す。
   「別の市区町村の学校のコード」とみなすのは、P29 でそのコードの学校の行政区域コードが学区データと違い、かつ P29 の学校名の設置者が
   学区データの設置者（`A27_002` から「立」と郡名を外したもの）と違うとき。設置者が同じなら、P29 の行政区域コードだけの誤りとみて、
   学校コードを id にする（福岡県：大野城市立下大利小学校が P29 では太宰府市のコード）。
3. **id**：学校コードが基本。学校コードが無い学校、上の2の学校、同じ学校コードがすでに使われている学校は「市区町村コード-番号」。
   学校は（学校コード, 市区町村）で区別する。

4. **誤記の訂正の表**（`pipeline/terms/source_corrections.csv`）。元データの値が誤記と分かり、根拠のあるものだけを、表で直してから使う。
   列は「データ名,学校コード,項目,元の値,直した値,根拠」。データ名は `P29`（国土数値情報「学校」）、項目は GeoJSON の属性名（`P29_004` など）。
   読み込んだ直後に、学校コード（`P29_002`）が合う地物の、その項目の値が「元の値」と同じなら「直した値」に置きかえる。
   ほかのすべての処理（設置者の判定、学校名、位置の引き当て）は、置きかえた値を使う。
   - 学校コードの地物がその県に無い行は、何もしない（表は全国で1つ）。
   - 値がすでに「直した値」なら、何もしない（元データが直ったとき）。
   - 値が「元の値」でも「直した値」でもなければ止める（表が古い）。表が無ければ止める。
   使った訂正は `report_XX.json` の `source_corrections` に {データ名, 学校コード, 項目, 元の値, 直した値} で出す。
   いまは1件：石川県の P29 で、珠洲市の若山小学校（`B117220500078`）の名前が「珠州市立若山小学校」になっている。
   所在地（`P29_005`）が「石川県珠洲市若山町…」、行政区域コードが珠洲市（17205）なので「珠洲市立若山小学校」に直す。
   若山小は学区データにある学校なので、推計は変わらない。直す前は、学区データに入っていない学校の候補を選ぶとき（珠洲市は配分率 0.89）に、
   上の1の判定で設置者が合わないとして `owner_mismatch_excluded` に出ていた。

## 学区データの無い市区町村（おおよその区域）

国土数値情報の小学校区データは、自治体によって提供されていない。福岡県では52市区町村分が収録され、福岡市・北九州市（政令指定都市の全区）などが含まれていなかった（2026-11-14、inspect で確認）。

これらの市区町村では、国土数値情報「学校」の位置を使う。

1. 学区データで配分できた子どもが5%未満の市区町村を「学区データなし」とみなす。
2. その市区町村の公立の小学校と義務教育学校を選ぶ。学校コードがあれば、先頭2文字が `B1`（小学校）か `C2`（義務教育学校）で、5文字目が `2`（公立）のもの。
   義務教育学校の名前はそのまま出す（「東山泉小中学校」など）。京都市東山区は公立の学校が2校とも義務教育学校で、以前は「学区データなし」になっていた。無ければ名前が「小学校」で終わり、附属・私立を含まないもの。休校の学校は使わない（下の「休校の学校は使わない」）。
3. メッシュに置いた各点のうち、学区に入らなかった点を、そのメッシュの市区町村の中でいちばん近い学校に割り当てる（ボロノイ分割と同じ考え方）。境界をまたぐメッシュ（`SHICODE` が `40133_40134` のもの）は、並んだ市区町村のうち学区データの無いものすべての学校を候補にする。学区に配分済みの点は使わないので、二重には数えない。
4. 地図には、割り当てた点の凸包を点線で描き、画面に「おおよその区域」であることを表示する。
5. 市区町村名は、P29 でその行政区域コードが付いた地物（学校の種類を問わない）の住所から市区町村名を取り、いちばん多いものにする（同数なら名前の順で先のもの）。
   最初の1件で決めると、コードの誤った1件で名前が変わる。岐阜県では、長野県下諏訪町の日進学園（学校コード `H2`、各種学校）が岐阜市のコード 21201 で最初に入っていて、岐阜市が「下諏訪町」になっていた（2026-11-17 に修正）。日進学園は `B1`・`C2` ではないので、候補にはならない。

**距離の測り方。** 経度・緯度の度のまま平面で測る近似。経度1度の長さは緯度によって違うので、経度の差に
**その点の緯度の cos** を掛ける：距離² ＝ ((点の経度 − 学校の経度) × cos(点の緯度))² ＋ (点の緯度 − 学校の緯度)²。
以前は県全体で1つの値（割り当てる点の緯度の平均の cos）を使っていた。福岡県（北緯33.0〜34.0度付近）で点ごとの値に変えると、
おおよその区域の学校のうち39校で推計（各年・各歳のどれか）が0.06人を超えて変わり、いちばん大きい学校で約13人だった（2026-11-15）。
学区データのある市区町村での当たり具合（`validate-approx`）でも同じ測り方を使う。

## 国土数値情報「学校」から学校を選ぶとき：休校の学校は使わない

国土数値情報「学校」（P29、令和5年度）には休校区分（`P29_007`）がある。「休校中」のコードは資料によって違う。
製品仕様書（第2.0版・第2.1版）では **9＝休校中**、コードリストのページ「休校コード」
（<https://nlftp.mlit.go.jp/ksj/gml/codelist/ClosedSchoolCode.html>）では 0（調査なし）・1（開校中）・**2（休校中）**。
実データ（全国の予行）にあるのは 1 と 9 だけだった。

1. P29 から学校を選ぶとき（上の「おおよその区域」の候補と、下の「学区データに入っていない学校」の候補）は、
   休校区分が **2 か 9（休校中）** の学校を使わない。ほかの意味の分からない値（空欄を除く）の学校も使わない。0 と 1 は使う。
2. 休校区分の列は、属性名が `P29_007` か、名前に「休校」を含む属性で、中身が1桁の数字（空欄を除く）だけのもの。
   見つからないデータでは、すべての学校を使い、そのことをログに出す。
3. 学区データ（A27）に載っている学校は、休校区分に関係なく、これまでどおり学区データの学校として使う。
4. 外した公立小学校は `report_XX.json` の `closed_schools_excluded` に、市区町村コード・学校名・休校区分の値・扱い
   （おおよその区域の候補から外した／補う学校の候補から外した／学区データにあるので学区の学校として使う／候補になる市区町村ではない）を出す。

## 政令指定都市で、学区データが市のコードで入っているとき

国土数値情報の小学校区データは、政令指定都市を区のコードではなく市のコード（静岡市 22100、浜松市 22130）で収録していることがある。
メッシュの `SHICODE` と国土数値情報「学校」の行政区域コードは区のコード（静岡市 22101〜22103、浜松市は再編前の 22131〜22137）。

1. 区と市の対応：`pipeline/terms/designated_city_wards.csv`（国土数値情報「行政区域コード」令和6年1月1日現在から作った、全国20市・178区。
   欠番の区＝再編前の区も、改正後のコードつきで入っている）。コードの並びでは決めない（札幌市の 01110 のように10の位をまたぐ区がある）。
2. 次の3つがそろう政令市を「学区データが市のコードで入っている」とみなす：学区データにその市のコードがある。メッシュ（と学校の位置）に
   その市のコードが無い。メッシュ（と学校の位置）にその市の区のコードがある。`report_XX.json` の `city_coded_districts` に警告として出す。
3. その政令市は、メッシュと学校の位置の区のコードを市のコードに読み替える。境界をまたぐメッシュ（`22101_22102`）は `22100` に、
   市の外とまたぐもの（`22103_22210`）は `22100_22210` になる。配分率、学区データなしの判定、補う学校の候補の範囲は市の単位になり、
   画面の市区町村も市で1つになる。
4. 学区データが区のコードで入っている政令市と、学区データの無い政令市（福岡市・北九州市）は、今までどおり区で分ける。
   区で分けて出す市区町村のコードが欠番の区（再編前）なら、今の区と名前が合わないので `report_XX.json` の `obsolete_ward_cities` に警告として出す。

## まとめた区域（福島県の浜通り、07999）

福島県のメッシュには、浜通りの13市町村（いわき市、相馬市、南相馬市、広野町、楢葉町、富岡町、川内村、大熊町、双葉町、浪江町、
葛尾村、新地町、飯舘村）の行政区域コードが無く、まとめて `07999` で入っている（4,104メッシュ）。国の推計
（国立社会保障・人口問題研究所「日本の地域別将来推計人口（令和5年推計）」）が、原子力発電所事故の影響が大きく長く続いているため、
この13市町村を1つの地域（浜通り地域）として推計しており、市町村別の推計値は無い。

扱いは `pipeline/terms/fukushima_hamadori.csv`（行政区域コード, 市町村名, まとめた区域のコード, 扱い, 2020年の5〜14歳, 2025年5月1日の児童数, 出典）で決める。

- **出す（注意書きつき）**：いわき市、相馬市、南相馬市、新地町、広野町、川内村
- **出さない**：楢葉町、富岡町、大熊町、双葉町、浪江町、葛尾村、飯舘村
- 線引き：令和2年国勢調査の5〜14歳人口が、令和7年5月1日の児童数（小学校＋義務教育学校の前期課程、市町村の合計）より少ない町村は出さない。
  推計の土台の2020年に町村内に住んでいた子どもが、いまの児童数より少なく、推計が実際とかけ離れるため。

計算は次のとおり。

1. **配分率と学区データなしの判定**：`07999` を1つの市区町村として扱う（配分率は `07999` 全体で1つ）。出す6市町村はどれも学区データがあるので、
   おおよその区域は作らない。「学区データに入っていない学校」の補いも、`07999` の配分率で判定する。
2. **出さない町村の学校**は、学区データにあっても P29 にあっても出力しない。
3. **扱わない区域**：次の子どもは、どの学校にも配分しない（ほかの市町村の学校に回さない）。
   - 出さない町村の学区（学区データ）に入る点の子ども（学区が重なる点は、ほかと同じく学区の数で等分した分）
   - `07999` が並ぶメッシュの点で、どの学区にも入らなかった点のうち、13市町村の公立の小学校・義務教育学校（P29、休校を除く）で
     いちばん近い学校が、出さない町村の学校である点の子ども（距離はおおよその区域と同じ測り方）。学区データの無い双葉町の区域は、これで決まる。
   これらの点は、ほかの補い（おおよその区域・学区データに入っていない学校）にも使わない。
4. **検査**：`report_XX.json` の `not_handled_2025` に扱わない区域の子ども（2025年）を出し、保存則は「配分＋未配分＋扱わない区域＝メッシュの合計」（全年）で確かめる。
   `combined_areas` に、市町村ごとの学校数・推計の合計（2025・2050年）・児童数との比・扱わない区域の子ども・1人未満で出なかった学校を出す。
5. **画面**：出さない町村は、市区町村の選択肢に選べない項目として「（このアプリでは あつかって いません）」と並べる（`missing` の `nothandled: true`）。
   出す6市町村（`combined: true`）には、学区データのある学校にも、おおよその区域の学校にも、注意書きを出す。

## 学区データのある市区町村で、学区データに入っていない学校

学区データのある市区町村でも、国土数値情報「学校」に公立小学校としてあるのに、学区データに入っていない学校がある
（福岡県では岡垣町の山田小・海老津小、宮若市の宮若西小、みやま市の瀬高小。どれも令和5年度の「学校」に学校コード付きであり、
番号も既存の学校の間にあるので、新設校ではなく学区データの収録漏れとみられる。これは推測で、理由は確かめていない）。
その学校の区域の子どもはどの学区にも入らず、学校を選べなくなるので、次のように補う。学区データのある学校の値は変えない。

**前提：学区のある学校の線引きは正しいとみなす。** したがって、どの学区にも入らなかった子どもは、学区データに無い学校のどれかに通うと考える。

1. 対象の市区町村：学区データのある市区町村すべて。配分率（学区に配分できた子どもの割合）が 0.9 未満か以上かで、下の3の当て方が違う。
   （以前は 0.9 以上の市区町村では補わなかった。2026-11-17 に、0.9 以上でも下の3のBの当て方で補うことにした。）
2. 補う学校：学区データの学校と、国土数値情報「学校」の公立小学校を、学校コードで突き合わせる。無ければ（市区町村, 設置者を外した学校名）で
   突き合わせる。どちらでも見つからない学校のうち、名前が「分校」で終わらず、休校でないもの。利用条件で学区を除いた市区町村（朝倉市）は、
   学区データなしの市区町村として上の方法で扱う。
3. 点の当て方。どちらも、距離は上と同じ測り方。
   - **A：配分率 0.9 未満の市区町村。** その市区町村で、どの学区にも入らなかった点（学区データなしの市区町村の補いで使った点は除く）を、
     **補う学校の中で**いちばん近い学校に当てる。学区のある学校は候補にしない。境界をまたぐメッシュ（`40383_40384` など）は、
     並んだ市区町村のうち A の市区町村の補う学校を候補にする（学区データなしの市区町村の補いと同じ扱い）。
   - **B：配分率 0.9 以上の市区町村。** どの学区にも入らず、ほかの補い（学区データなしの市区町村の補いと A）にも使っていない点のうち、
     その市区町村の公立の小学校・義務教育学校（国土数値情報「学校」で、学校コードの先頭2文字が `B1` か `C2`、5文字目が `2`。
     学校コードが無ければ名前が「小学校」で終わり、附属・私立を含まないもの。休校の学校を除く。学区データの学校・分校も含む）の中で
     いちばん近い学校が**補う学校**になる点だけを、その補う学校に当てる。いちばん近い学校が学区データの学校や分校になる点は、
     どの学校にも当てない（学区のすき間の点が、遠くの補う学校に集まらないように）。
     境界をまたぐメッシュは、並んだ市区町村のうち B の市区町村の学校（補う学校と、それ以外の上の学校）をまとめて候補にする。
     候補の学校は、休校のほかは外さない（設置者の名前が市区町村と合わない学校も候補に入れる。補う学校の選び方の設置者の判定とは別）。
     割り振りは A のあとに行う。
4. 補った学校は「おおよその区域」として扱い（`approx: true`）、地図は点線の凸包、画面では学校だけに注意を出す（市区町村全体には出さない）。

福岡県（2026-11-15）：補った学校の2025年の推計は 山田小 657.6・海老津小 539.0（岡垣町）、宮若西小 438.1（宮若市）、瀬高小 424.5（みやま市）。
このうち境界をまたぐメッシュからの分は 岡垣町 6.6、みやま市 23.4。3市町の配分率は補ったあと 1.0 になり、県全体の未配分は 1.1% から 0.3% に下がった。

`build` は、配分した合計 ＋ 補った合計 ＋ 未配分 ＝ メッシュの合計（全年）と、学区のある学校の値が補う前と同じであることを確かめ、合わなければ止まる。
`report_XX.json` の `filled_missing_schools` に、補った学校の数を市区町村ごとに出す（2025年の推計が1人未満で出力しなかった学校は `filled_missing_dropped_small`）。
`validate-approx` は、学区のある学校だけを比べる。

### 割り当たる点が無い学校

おおよその区域と「学区データに入っていない学校」の補いでは、点をいちばん近い学校に当てる。どの点もほかの学校のほうが近いと、
その学校には点が1つも当たらず、区域（凸包）も推計も作れない。このような学校は出力しないが、黙って抜かず、
`report_XX.json` の `schools_without_points` に {市区町村コード `city`、学校名 `name`、学校コード `code`、どちらの補いか `how`} で出す。
`how` は「おおよその区域」か「学区データに無い学校」。2025年の推計が1人未満の学校（`dropped_small`）とは別の一覧である。

予行（2026-11-16）では2校だった。どちらも、学校のまわりに推計のメッシュが無い（推計のデータに入っているメッシュでいちばん近いものが、
防府市の野島小から 5.3km、京都市右京区の水尾小から 3.2km）。まわりのメッシュはほかの学校のほうが近い。
水尾小は、義務教育学校を候補に入れる前は、近くの宕陰小中学校・京都京北小中学校が候補でなかったため、右京区北部の点が集まっていた。

本当の学区は道路や町丁目で区切られ、学校から最も近い場所とは限らない。したがって学校ごとの人数のずれは、学区データのある市区町村より大きい。市区町村全体の合計は変わらない。学校の位置データも無い市区町村は「学区データなし」として選択肢に出し、計算しない。

## 検査

`build` は毎回、次を出します（`--opendata` を付けると `report_XX.json` に保存）。

- 保存則：配分した合計 ＋ 未配分 ＝ メッシュの合計（誤差は 0 になるはず）
- 未配分の割合：学区データが無い区域の大きさの目安
- 市区町村ごとの配分率：0.9 未満の市区町村は警告。学区データが未整備の可能性が高い
- 重なりの割合：学区ポリゴン同士の重複の目安
- 2025年の推計が1人未満で出力しなかった学区の一覧
- 割り当たる点が無く出力しなかった学校の一覧（`schools_without_points`。上の「割り当たる点が無い学校」）

## 読めないときに、黙って別の値で続けない

読めないときや判定できないときに、別の値で黙って続けると、間違った数字がそのまま出る。次のように、止めるか report に出す（2026-11-16 に見直した）。

| 場所 | 以前 | いま |
|---|---|---|
| `validate-approx`・`build` で、学校の位置データ（P29）の属性を判定できない | 学区の重心で代えて続けた（予行の青森県・岩手県） | 止める |
| 政令市の判定に使う P29 を読めない | P29 の確認なしで判定を続けた | 止める |
| 利用条件の一覧（`school_district_terms_R5.csv`）が無い | 学区を除かずに続けた | 止める |
| 確認待ちの表・まとめた区域の表・政令市の区の表が無い | （新しい表）／区の表は空として続けた | 止める |
| まとめた区域（07999）の学校の位置が無い | ― | 止める（学区の外の点を市町村に分けられない） |
| メッシュの年齢階級の列に、空欄でも数値でもない値がある | 0として続けた | 止める（空欄は秘匿メッシュなので0） |
| GML のメッシュで、属性の数がほかと違う | そのメッシュを捨てた（子どもが合計から消える） | 止める |
| `data/index.js` を読めない | 空の一覧として書き直した（ほかの県が消える） | 止める |
| 学区データのある学校の位置が P29 に無い | 学区の重心（CSV の `loc_source` だけに出た） | 学区の重心にして `location_fallback` に出す |
| P29 に休校区分の属性が無い | 休校の学校も使い、ログだけに出した | 同じく使い、`closed_field: null` を report に出す |
| 市区町村の名前が分からない | 画面にコードを出した | 同じ。`cities_without_name` に出す |
| おおよその区域・補う学校で、割り当たる点が無い学校 | 黙って出力しなかった | 出力せず、`schools_without_points` に出す |

止めないもの：`build-all` の県ごとの失敗（ほかの県は続け、結果に「失敗」と出す）、`_scan_inputs` で読めないファイル（ログに出し、足りないファイルとして結果に出る）、
2025年の推計が1人未満の学校（`dropped_small`）。

## 公式のコード表で確かめたこと（2026-11-14）

国土数値情報「メッシュ別将来推計人口（R6国政局推計）」のデータ項目一覧で、次を確認した。

- 列は `MESH_ID`（メッシュコード）、`SHICODE`（市町村コード）、2020年の総数、そのあと年ごとに98項目。
- 年ごとの並びは、秘匿記号 `HITOKU20XX`、合算先 `GASSAN20XX`、男女計の秘匿無し総数 `PTN_20XX`、総数 `PT00_20XX`、5歳階級 `PT01`〜`PT20`（01＝0〜4歳）、合計 `PTA`（0〜14歳）〜`PTE`、比率 `RTA`〜`RTE`。続いて男（PM）、女（PF）が同じ並び。
- 秘匿されたメッシュは記号 `*` で値は0。その人口は記号 `@` の合算先メッシュに足されている。したがって、値をそのまま使えば合計は保たれる。

テスト用の合成データ（`pipeline/tests/test_pipeline.py`）は、この並びと秘匿・合算をそのまま再現している。これにより判定の不具合を1つ見つけて直した。秘匿記号の列（空欄は0と読まれる）と総数の列が並ぶため、「0＋0＋総数＝総数」を年齢の内訳と取り違えていた。いまは、3列とも中身のある数字であることを条件にしている。

## 学校名の読み（ひらがなで さがす）

子どもが「りゅうおう」のように平仮名で学校をさがせるよう、各校に読み `kana`（平仮名、1〜2個）を持たせる。
読みは画面に出さない（検索にだけ使う）。学校の位置と人数は作り直さない（`app/data` には `kana` を足すだけ）。
作った読みの一覧と数は [KANA.md](KANA.md)（`make-kana` が書く）。

### 決まり

1. **学校名を分ける**。先頭の設置者（「姫路市立」など）を外し、次の形に分ける。
   - 「〇〇小学校△△分校」（「〇〇小△△分校」も）→ 語幹「〇〇」＋「しょうがっこう」＋ 分校名「△△」＋「ぶんこう」。分校名が無ければ「ぶんこう」だけ。
   - 末尾の種別：義務教育学校＝ぎむきょういくがっこう、小中一貫学校＝しょうちゅういっかんがっこう、小中一貫校＝しょうちゅういっかんこう、
     小中学校＝しょうちゅうがっこう、小学校＝しょうがっこう、学園＝がくえん、学校＝がっこう（長いものから当てる）。
   - 先頭の「義務教育学校」（「義務教育学校香春思永館」など）＝ぎむきょういくがっこう。
   - どれにも当たらなければ、名前全体を語幹として読む。
2. **町字で読む**（元＝`town`）。語幹の頭から、同じ市区町村の町字の名前で、いちばん長く一致するものを探し、その読みを使う。
   - 比べる名前：大字・町名と小字。それぞれ、そのままの名前に加えて、先頭の「大字」「字」を外したもの（読みの先頭の「オオアザ」「アザ」も外す）と、
     末尾の丁目（「一丁目」「1丁目」、読みの「…チョウメ」）を外したもの。さらに、末尾の「町」「村」を外したもの
     （読みの末尾の「チョウ」「マチ」（町）、「ムラ」「ソン」（村）も外す。外したあと名前が2文字以上で、読みの末尾が合うときだけ。
     日比津町・近見町・上南摩町のように、学校名には「町」が付かないため）。
     町字データの読みは小さい字を大きく書く（「イツチヨウメ」「チヨウ」）ので、読みの末尾（丁目・町・村）は小さい字を大きくしてから比べる
     （2026-11-18 まで、丁目の読みは小さい字の形でしか比べておらず、実物では丁目を外したものが作られていなかった。make-kana をかけ直すと直る）。
   - 政令市を市で1つにまとめた市区町村（`app/data` の市区町村コードが `pipeline/terms/designated_city_wards.csv` の「市のコード」のもの）は、市内の全区の町字を使う。
     まとめた区域（福島県 07999）は、まとめた市町村すべての町字を使う。
   - 同じ名前で読みが違う町字が同じ市区町村にあるときは、行の多い読み（同じ数なら五十音順で先のもの）を使う。廃止された町字も比べる（学校名には古い地名が残るため）。
   - 頭に町字が当たらず、頭が方角・番号の表の語なら、その語の後ろから町字を探す（「東竜王」→ ひがし＋竜王）。
   - 町字の後に残った部分は、**方角と番号の表**（東・西・南・北・中央・中・東部・西部・南部・北部・中部・第一〜第十。「第1」も）でぜんぶ読めればそれで、
     読めなければ辞書（下の3）で読む。どちらでも読めなければ、町字の読みは作らない。
   - 分校名も同じように読む（町字で読めなければ辞書で読む）。語幹か分校名のどちらかで町字を使ったときに、町字の読みとする。
3. **辞書で読む**（元＝`dict`）。語幹全体（分校名も）を SudachiPy（辞書 SudachiDict full、分割は C）で読み、各語の読みをつなぐ。
   読みに漢字が残る語（辞書に無い語。数詞の「一」などは辞書に無くても読みが付く）があれば、辞書の読みは作らない。
   - 「ヶ」「ケ」：辞書には、まず学校名のまま渡して読む。学校名に置き換えられる字があれば、それを「が」に置き換えたものも読み、
     両方を辞書の読みの候補にする（学校名のままの読みが先）。置き換える字は、「ヶ」は前の字を問わず、「ケ」は前が漢字か平仮名で後ろが漢字のとき
     （草ヶ江、つつじケ丘、りんどうヶ丘）。辞書は「金ケ崎」「三ヶ日」をそのままなら かねがさき・みっかび と読めるが、
     「草ヶ江」をそのままだと「くさゖこう」と読み、「鈴ケ森」「巴ケ丘」は置き換えないと「け」と読むため。
     読みに「ゕ」「ゖ」が残ったら、その読みは捨てる（町字・名前のかなの読みも同じ）。
   - 語末の「丘」が「おか」以外（「きゅう」「たかし」など）に読まれたら、「丘」の前までを辞書で読み、「がおか」を付けた読みと「おか」を付けた読みの
     両方を候補にする（「がおか」が先。高丘 → こうがおか・こうおか、鷹丘 → たかがおか・たかおか）。前が「が」「の」で終わるときは「おか」だけ
     （「つつじが丘」→ つつじがおか。「ががおか」は作らない）。霧丘 → きりがおか・きりおか。
     辞書で読む部分（町字の後に残った部分も）にだけかけ、町字の読みにはかけない。
   - 候補の並べ方：学校名のままの1つ目、置き換えたものの1つ目、学校名のままの2つ目、置き換えたものの2つ目（同じ読みは1つに）。
     町字の後に残った部分を辞書で読むときは、1つ目の候補を使う。語幹と分校名の両方を辞書で読むときは、それぞれの n 番目どうしをつなぐ
     （候補が1つしかない部分は、その1つを使う）。
4. **名前のかな**（元＝`name`）。語幹（と分校名）が平仮名・片仮名・「ー」だけなら、それを平仮名にして読みとする（「あずま小中学校」→ あずましょうちゅうがっこう）。
   かなと漢字が混ざった語幹は 2・3 で読む（かなの部分はそのまま読みに入る）。
5. **残し方**。町字の読みを先に、辞書の読みの候補を上の順に並べ、同じ読みは1つにして、先頭から2つまで残す（町字と辞書の1つ目が同じなら元＝`town`）。どちらも作れなければ読みなし（`kana` を付けない）。
   読みは平仮名と「ー」だけにする（片仮名は平仮名に。それ以外の字が残る読みは捨てる）。
6. **手直し**。`pipeline/terms/school_kana.csv`（学校コード, 読み, 理由）にある学校は、自動の読みを使わず、その表の読みで置き換える
   （1校に2行まで。読みを空にした行は「読みを付けない」）。

### 作り方と、できるもの

## 読み取りの限界

- 学区に住む子どもの推計であり、在籍児童数ではない（私立・国立、学校選択制、区域外就学）。
- 推計は市区町村の推計に合うよう調整されているが、小さな区域ほど誤差が大きい。
- 学区は整備年度の区域。以後の統合や区域変更は入っていない。
- 国の学級編制の標準で計算しており、自治体独自の少人数学級は入っていない。
- 福島県の浜通り13市町村は、国の推計が13市町村で1つ。市町村ごとの数字は、まとめた区域の推計をメッシュごとに集計したもの（上の「まとめた区域」）。

## 利用条件

- 国土数値情報は、データごとに利用条件が定められている。小学校区データは自治体ごとに条件が異なり、商用利用できない自治体がある。
- このアプリは非営利の教育目的だが、公開前にダウンロードページの利用条件一覧で、対象の自治体を確認する。条件に合わない自治体は生成対象から外す。
- 利用条件に「再配布不可」を含む市区町村の学区データは使わない（学区データなしとして、おおよその区域で計算する）。
- **確認が取れるまで使わない市区町村**：`pipeline/terms/pending_confirmation.csv`（行政区域コード, 自治体名, 理由, 出典）。
  いまは小田原市だけ（利用条件が「条件公開」で、特記条件に「利用開始前に利用内容について市の確認を受けること。」）。
  確認が取れるまで学区データを使わず、おおよその区域にする。「学区は めやす」の表示（note）も付けない。
- 使わなかった市区町村は `report_XX.json` の `excluded_by_terms` に、コード・名前・理由（「利用条件「商用利用・再配布不可」」「確認待ち：…」）で出す。
- **出典の書き方**：県のデータ（`pref_XX.js` の `source`）に、使った3つのデータの名前・ページの URL・取得日（`datasets`）と加工者（`processor`）を持たせる。
  表示は「出典：「国土数値情報（○○データ）」（国土交通省）（URL）（○年○月○日取得）を加工して作成。加工：わたしの学校2050（h-kazuki-pixel）」。
  先生向けページには県ごとに全部（`data/index.js` の `datasets` から）、はじめの画面と提案カードには短い形
  （「出典：国土数値情報（国土交通省）を加工して作成。加工：わたしの学校2050（h-kazuki-pixel）」）。README にも書く。
  取得日はダウンロードした日（福岡県 2026-11-14、ほかの46都道府県 2026-11-16）。生成のたびに変わらないよう、`build --retrieved` で渡す
  （`build-all` は `--retrieved` か、入力フォルダの `retrieved.csv`）。無ければ取得日を空にして `retrieved_missing: true` を report に出す。
  国が作ったものに見える書き方をしない（学校ごとの数字は「データの よそう」。「国の 推計」と書くのは、もとのメッシュの推計のことだけ）。
